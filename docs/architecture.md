# Початкова архітектура EcoShare

## Склад системи
Сервер NestJS — один застосунок із функціональними модулями.
React — окремий клієнт. PostgreSQL/Prisma — заплановане постійне сховище.
У поточному демонстраційному інкременті застосовується пам’ять процесу.

## Бізнес-модулі
- Auth/Users: поточний крок — моделі Guest/Resident і публічний контракт.
- Listings: поточний крок — модель, репозиторій, стрічка та пошук.
- Reservations: подальша реалізація, ітерація 2.
- Contact: подальша реалізація, ітерація 2.
- Notifications: подальша реалізація, ітерація 2.
- Moderation: подальша реалізація, ітерація 3.

## Спільний формат ListingView
id: string
title: string
description: string
category: string
dormitory: string
status: available | reserved
ownerName: string

Email, contact та пароль користувача не входять до ListingView.

## Погоджені демонстраційні запити
GET /api/health
GET /api/users/demo
GET /api/listings
GET /api/listings?search=ДРИЛЬ

Поточний API демонстраційний. Реєстрацію, активацію, JWT, перевірки ролей
та повний захист доступу буде додано наступними задачами першого спринту.
Демо-профіль не є поточним авторизованим користувачем.

## Домовленість про дані
Демонстраційний користувач: resident-demo, ім’я: Демо мешканець.
Після додавання seed-даних: listing-drill доступний, listing-book заброньований.
Приховані й закриті записи залишаються лише в репозиторії та не потрапляють у стрічку.

## Відповідальність папок
src/server — сервер, src/client — клієнт, prisma — початкова схема БД,
tests — автоматичні перевірки, docs — документація.
