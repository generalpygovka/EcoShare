# EcoShare

EcoShare — вебсервіс взаємодопомоги для мешканців гуртожитків. У межах лабораторної роботи №4 реалізовано базову структуру проєкту та демонстраційний сценарій: користувач відкриває стрічку й знаходить потрібне оголошення за текстом.

## Що реалізовано

- **Модульний моноліт на NestJS.** Сервер працює як один застосунок із модулями Auth/Users і Listings.
- **Auth/Users.** Клас `Resident` успадковує `Guest`. Через контракт `IAuthUsers` інші модулі отримують публічні дані користувача без електронної пошти й контактів.
- **Listings.** Є модель `Listing` із перевіркою назви та репозиторій у пам’яті. Стрічка показує доступні й заброньовані оголошення. Пошук працює за назвою та описом незалежно від регістру.
- **React і TypeScript.** Клієнт завантажує оголошення з API, надсилає пошуковий запит і показує стани завантаження та помилки.
- **Prisma.** Підготовлено початкову схему PostgreSQL із моделями `User` і `Listing` та зв’язком між оголошенням і його власником.

Під час запуску сервер створює чотири демонстраційні оголошення в пам’яті. У стрічці видно два з них, оскільки приховані та закриті записи відфільтровуються. Для запуску демонстрації PostgreSQL не потрібна.

## Локальний запуск

Потрібні Git і Node.js 24 з npm. Усі команди нижче запускаються з кореня репозиторію.

```bash
git clone https://github.com/generalpygovka/EcoShare.git
cd EcoShare
```

**Термінал 1 — сервер:**

```bash
npm --prefix src/server ci
npm --prefix src/server run dev
```

**Термінал 2 — клієнт:**

```bash
npm --prefix src/client ci
npm --prefix src/client run dev
```

Залиш обидва процеси запущеними й відкрий [http://localhost:5173](http://localhost:5173). У стрічці мають з’явитися «Дриль Bosch» і «Книга з програмування». Введи `ДРИЛЬ` і натисни **Знайти** — залишиться одне оголошення.

## API

Сервер доступний за адресою `http://127.0.0.1:3000`.

| Запит                            | Результат                                                |
| -------------------------------- | -------------------------------------------------------- |
| `GET /api/health`                | Стан сервера та назва проєкту.                           |
| `GET /api/users/demo`            | Публічний профіль демонстраційного мешканця.             |
| `GET /api/listings`              | Оголошення, доступні для перегляду у стрічці.            |
| `GET /api/listings?search=ДРИЛЬ` | Оголошення, назва або опис яких містять пошуковий текст. |

## Тести та CI

Після встановлення залежностей запусти:

```bash
npm --prefix src/server test
npm --prefix src/client run build
```

Серверна команда збирає проєкт і запускає **10 автоматичних тестів**: 4 доменні та 6 API-тестів. Вони перевіряють наслідування, валідацію назви, роботу з репозиторієм, фільтрацію, пошук і склад публічних відповідей. Сценарії та результати описано в [плані перевірок](docs/test-plan.md).

Щоб окремо перевірити схему Prisma, створи `.env` як копію `.env.example`, якщо `.env` ще немає, і виконай:

```bash
npx --yes prisma@6.19.0 validate --schema prisma/schema.prisma
```

[GitHub Actions](https://github.com/generalpygovka/EcoShare/actions) запускає серверні тести, збирає React і перевіряє схему Prisma після push та для pull request.
